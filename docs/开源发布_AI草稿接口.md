# AI 病历草稿接口（开源公开文档）

> 本系统**不内置任何 LLM 调用**。AI 草稿箱的定位：你用任何方式（自建语音管线、大模型、
> 手写脚本）生成病历草稿 Markdown，丢进约定目录，用摄入命令导入 → 医生在 Web「AI 草稿箱」
> 里审核确认后才成为正式病历。不接 AI 时，病历手写流程完全不受影响。
>
> 本文随开源版发布，是 AI 草稿箱的对外接口说明（公开文档）。

## 数据流

```
你的生成器(任意) → <records-dir>/<YYYY-MM-DD>/*.md
    → python3 -m local_app.ingest_ai_records --date <YYYY-MM-DD>
        ├─ 唯一匹配到患者 → medical_records(draft_status=ai_draft)  → 草稿箱「待审」
        └─ 未命中/重名     → ai_unclaimed_drafts                    → 草稿箱「待认领」
    → 医生在 Web UI 审核：确认入库 / 认领到患者 / 丢弃
```

## 草稿 Markdown 格式

一份草稿 = 一个 `.md` 文件，头部字段行 + `【】`正文块：

```markdown
姓名: 张三
性别: 男
年龄: 42
就诊时间: 2026-07-08 10:30
主诊医生: 李医生
诊室: 诊室1

【主诉】
右下后牙冷热刺激痛 3 天。

【现病史】
…

【检查所见】
6┐ 深龋近髓，叩痛(+)。

【诊断】
6┐ 急性牙髓炎

【治疗明细】
6┐ 开髓引流，安抚。

【医嘱】
勿用患侧咀嚼，3 日后复诊。

【复诊计划】
一周内根管治疗。

【收费明细】
开髓引流 300 元
```

规则：

| 项 | 说明 |
|---|---|
| 头部字段 | `姓名/性别/年龄/就诊时间/主诊医生/诊室`，冒号中英文均可；姓名用于匹配患者 |
| 正文块 | `【主诉】【现病史】【检查所见】【诊断】【治疗明细】【医嘱】【复诊计划】`，缺块可省 |
| 收费明细 | 单独归档进草稿附加信息，不直接生成账单 |
| 牙位 | Palmer 记法（`6┐`=右下6、`└E`=左上乳牙E），解析器自动提取牙位集合 |
| 匿名场景 | 姓名可写代号，配 `--mapping 映射.json`（`{"代号":"真名"}`）在摄入时还原匹配 |

## 摄入命令

```bash
# 处理某天
python3 -m local_app.ingest_ai_records --date 2026-07-08

# 处理全部日期子目录
python3 -m local_app.ingest_ai_records --all

# 自定义草稿目录（默认 local_app/data/ai_records，或环境变量 DENTAL_AI_RECORDS_DIR）
python3 -m local_app.ingest_ai_records --date 2026-07-08 --records-dir /path/to/records
```

行为约定：

- **幂等**：按 `source_file` 去重，重复跑安全。
- **匹配口径**：姓名在患者表**唯一命中**才入草稿；重名/查无此人 → 「待认领」，由前台在草稿箱手动挂到正确患者。
- **隐私**：报告只输出计数；异常留痕只含短 hash，明文定位映射写在数据区 `ingest_errors.log`（不进版本库）。
- 草稿入库为 `draft_status=ai_draft`，**不算正式病历**，不进病历完整性统计，医生确认后才转正。
